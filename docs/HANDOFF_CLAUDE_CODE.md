## 4. Arquitectura
- **Edge (Pi), nodo ACTIVO** `edge_pose/epp_edge/`: Camera → máquina de estados IDLE (solo MOG2) → PERSON_CHECK (YOLOv8n-pose 320px) → ACTIVE (pose 320px + EPP 640px hasta `epp.max_fps`, `placement.py` asocia EPP↔persona por keypoints y evalúa colocación por persona/mano) → episodio con veredicto (`cumple`, `faltantes`, `mal_colocados`) → `cloud_v2.py`: outbox idempotente (SQLite) → Uploader (imágenes → sidecar JSON → batch.create en Firestore + daily_stats Increment), representando cada episodio como pseudo-detección `episodio_conforme`/`episodio_no_conforme` (`clase_id` 100/101) para que el dashboard lo muestre sin cambios de backend. StreamWorker solo con lease activo. DeviceControl por Firestore `on_snapshot`. HealthReporter. Instalado en `~/epp-edge` en la Pi (no en `/opt/epp-edge/app`, que sigue siendo el clon git de referencia); systemd `epp-edge@<usuario>` (plantilla, distinto nombre de unit que el nodo viejo). Modelos NCNN en `edge_pose/models/` (gitignorado, no se versiona).
- **Edge (Pi), nodo en el repo pero NO desplegado** `raspberrypi/epp_edge/`: picamera2/USB/file → LatestSlot → InferenceWorker (NCNN, imgsz 416, ≤5 fps, un solo modelo EPP) → Aggregator → Outbox SQLite WAL → Uploader idempotente (imágenes → sidecar JSON → batch.create en Firestore + daily_stats Increment). StreamWorker solo con lease activo. DeviceControl por Firestore `on_snapshot`. HealthReporter. Systemd `epp-edge` (sin plantilla) — deshabilitado en la Pi desde 2026-10-16.
- **Cloud Run** `orchestrator-service` (`backend/epp_api/`, max-instances=1, min 0, 1 worker uvicorn): API FastAPI + relay WebSocket + SPA React en el mismo origen.
  - Protocolo de video: 8 bytes big-endian uint64 `captured_at` ms + JPEG.
  - Lease: `device_control.stream_requested` + `lease_renewed_at` (LEASE_SECONDS 90, renovado cada /3).
  - Auth: Google Identity Services ID token → cookie firmada `epp_session` (itsdangerous); roles viewer/operator/admin; CSRF con header `X-Requested-With: epp-web`; revalidación de rol cada 60 s; rate limit 10/min/IP.
- **Data lake** en GCS bucket `epp-detection-v1-lake`: `raw/images|thumbs|events/device=<id>/dt=<fecha>/<event_id>.*`, create-only (`if_generation_match=0`).
- **BigQuery** dataset `epp_lake` (tabla externa `raw_events`, object table `raw_images`, `events` curada con MERGE diario, vistas gold).
- Contrato v2 del evento JSON: `capture` anidado (`capture.uri`, `capture.thumb_uri`).
- **Frontend** `frontend/`: React 19 + TS estricto + Vite, React Router, TanStack Query, Tailwind v4 con tokens, Radix, lucide, Recharts envuelto en componentes que respetan las reglas de dataviz, Vitest/Testing Library/MSW, Playwright + axe, pnpm. Guía de diseño en `docs/DESIGN_SYSTEM.md`.

- **`cv2.imwrite`/`cv2.imread` fallan en silencio con rutas que tienen tildes** en Windows (esta laptop: usuario `César Pérez`, con "é"). `imwrite` devuelve `False` sin excepción; `imread` devuelve `None`. Confirmado reproduciéndolo aparte. `cv2.VideoCapture` para LEER un video SÍ tolera rutas con tildes (usa otro backend internamente) — el problema es específico de leer/escribir imágenes sueltas. Para cualquier prueba local que escriba JPEGs (como correr `edge_pose` o `raspberrypi` contra un video), usar como `DATA_DIR`/`snapshots_dir` una ruta sin tildes (p. ej. el scratchpad, que ya usa el nombre corto `CSARPR~1`), no una bajo `C:\Users\César Pérez\...`.
- **`gcloud ... --field-config=field-path=X,order=Y` falla con "Exactly one of 'order'... must be specified" al correrlo tal cual desde PowerShell** (aunque la sintaxis es la del `--help`) — es un problema de cómo PowerShell pasa las comas/`=` al ejecutable. Se arregla envolviendo cada flag completo entre comillas: `"--field-config=field-path=X,order=Y"`. Los scripts de `infra/*.sh` no tienen este problema porque corren en bash, no PowerShell.
- **Los índices compuestos de Firestore son direccionales**: un índice con `end_ts` descendente NO sirve para una consulta que filtra `end_ts > X` y ordena `end_ts` ascendente (y viceversa) — hace falta un índice por cada combinación de dirección realmente usada por una consulta con rango + orden. Causó el 500 de `/api/devices/{id}/summary` y `/events` (ver §6, §7).
- **`edge_pose/install.sh` corre como el usuario normal (sin sudo) para el `rsync` del paso 2** — si los modelos se colocan a mano en el origen con `sudo mv`/`sudo chown root:root` (para que coincida con el resto de `/opt/epp-edge/app`, que sí es root-owned), el `rsync` no root no puede ni abrir esas carpetas ("Permission denied"). Hay que dejarlos con dueño el mismo usuario que corre `install.sh` (`chown -R vizia:vizia`), no root.
- **El wheel de `torch` para aarch64 (~100+ MB) se puede corromper a medias si la Wi-Fi de la Pi se corta durante la descarga**, dando un error de runtime engañoso (`ImportError: .../libtorch_cpu.so: undefined symbol: sbgemm_`, parece un problema de versión de OpenBLAS pero es el archivo incompleto). Antes de investigar BLAS/versiones, reinstalar limpio: `pip install --no-cache-dir --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cpu`.
- **`gcloud run deploy --source=.` usa Buildpacks en silencio (sin avisar) si no encuentra un `Dockerfile` en el directorio actual** — en vez de fallar. Verificar `Get-Location` / `Test-Path .\Dockerfile` antes de desplegar; el `Dockerfile` de este repo vive en la raíz, no en `backend/` ni `raspberrypi/`.
- **Flags de `gcloud` con comas dentro de un solo valor** (`--set-secrets="A=a:latest,B=b:latest"`, `--set-env-vars="X=1,Y=2"`) **necesitan comillas explícitas en PowerShell**, igual que `--field-config` (ver abajo) — sin comillas, la coma se pierde o se reemplaza por un espacio y `gcloud` lo interpreta como un spec inválido.
- **El flujo OAuth interactivo de `bq mk --transfer_config` (consultas programadas) no funciona ni con `!`**: pide pegar un código de verificación por `stdin`, y ninguna de las dos terminales (la del agente, la del usuario vía `!`) tiene un `stdin` real para eso — da `Got EOF; exiting`. Hay que crear la consulta programada a mano desde la Consola de BigQuery (Scheduled queries), no por CLI. (El login normal de `gcloud auth application-default login` sí funciona con `!`, porque abre un navegador real en vez de pedir pegar un código.)
- **`bq query` por stdin desde PowerShell corrompe el SQL** (error `Illegal input character "\357"`, un BOM mal interpretado) incluso reescribiendo el archivo sin BOM — es un problema de cómo PowerShell canaliza bytes a un ejecutable nativo. Pasar el SQL como argumento directo en vez de por stdin, **sin comentarios `-- ...`** (si alguna línea del SQL empieza con `--`, `bq` la interpreta como una flag desconocida) y **colapsado a una sola línea** (un argumento multilínea se trunca a la primera línea al pasarlo a un ejecutable nativo desde PowerShell).
- Las **keys de SA eliminadas pueden seguir apareciendo en `gcloud iam service-accounts keys list` por unos segundos** después de borrarlas (aunque el comando de borrado ya confirmó éxito) — es propagación/caché de listado, no un fallo del borrado; reintentar el listado tras una breve espera.
- **Un servicio de GCP puede ser dependencia obligatoria de otro que sí se usa**: `pubsub.googleapis.com` resultó ser dependencia de `cloudbuild.googleapis.com`/`containerregistry.googleapis.com` (los deploys los necesitan); `gcloud services disable` avisa de esto y hay que respetarlo (no forzar con `disable_dependent_services=true`), aunque el script de turno (`07_pubsub_teardown.sh`) esperara poder deshabilitarlo sin problema.
